# Hi, I'm Anurag 👋

I'm an AI product manager. I lead teams that ship AI products, and I build the Claude workflows my own product work runs on.

Six years in product, 20 products shipped, 16 of them AI first, across health, fintech, automotive, education and gaming. Most of my work starts the same way: a release decision that a demo can't settle. I build the smallest version that can answer it, test it against a fixed set of cases, and write the release rule down before I see the result.

## Start here: three repos you can run in 30 seconds

Each runs offline with Python 3.10 or newer, no packages and no API key.

| Repo | What it shows |
|---|---|
| [**ai-product-evals**](https://github.com/aragjha/ai-product-evals) | Should the new prompt ship? A written release rule says HOLD, and why. |
| [**claude-pm-os**](https://github.com/aragjha/claude-pm-os) | Meeting notes to brief, tickets, QA checklist and release note, with a human gate at each step. |
| [**evidence-review-lab**](https://github.com/aragjha/evidence-review-lab) | Every extracted contract term points at the clause it came from; doubtful ones go to a reviewer. |

Results in these repos are labelled **fixture**: produced by a deterministic stand in, not a language model, so anyone can reproduce them for free. All data in them is invented. Live Claude runs are built and tested but not run yet.
